## 1. プロジェクト概要

### アプリの目的

「オトクエスト」は **スマート購買最適化プラットフォーム** である。  
ユーザーが日用品・家電などを購入する際に、楽天市場・Yahoo!ショッピング・Amazon・ヨドバシなど複数の EC プラットフォームを横断して比較し、**ポイント還元・クレジットカード特典・キャンペーンを加味した「実質価格」で最安値を自動判定**する。

RPG ゲームをモチーフにした UI テーマ（「冒険者の館」「ギルドポイント（GP）」「レベル・クラス」）を採用し、節約行動をゲーミフィケーションしているのが特徴。

## 2. 主要機能と仕組み

### 2-1. 実質価格の計算ロジック（`realPrice.ts`）

#### 計算式

```
実質価格 = 表示価格
         - クーポン割引額（現在は 0 で固定）
         - floor(表示価格 × 合計還元率(%) / 100 × ポイント利用頻度)

合計還元率 = API の point_rate + カード追加還元率
```

#### 関数の役割

| 関数名 | 説明 |
|--------|------|
| `getBestCardForSource(source, userCards)` | ユーザー保有カードの中から指定プラットフォームで最高還元率のカードを選ぶ |
| `enrichItem(item, source, userCards, couponDiscount)` | ApiItem に実質価格計算結果を付加して `EnrichedItem` を返す |
| `rankItems(items)` | 実質価格で昇順ソート。±100円以内の同等価格はカード還元率の高い方を優先 |

#### 主要型定義

```typescript
interface ApiItem {
  itemName, shop, price, point_rate,
  review_average, review_count, url, imageUrl
}

interface EnrichedItem extends ApiItem {
  source: "楽天市場" | "Yahoo!ショッピング";
  couponDiscount: number;   // クーポン割引（現在 0）
  cardName: string;         // 適用カード名
  cardRate: number;         // カード追加還元率（%）
  totalRate: number;        // point_rate + cardRate
  usabilityRate: number;    // ポイント利用頻度（0〜1）
  pointValue: number;       // 実質ポイント価値（円換算）
  realPrice: number;        // 実質価格（円）
}
```

#### リアル API モードのフロー

```
ユーザーが検索 → searchBothApis(keyword)
```

### 2-5. スマート最適化エンジン（スコアリング）

「単純最安値」ではなく、以下を加味した **最適スコア** で順位付けする。

```typescript
// calcOptimizedScore() の計算ロジック
ポイント実質価値 = points × usabilityRate
安全性ペナルティ = trustScore < 70  → price × 5%
               = trustScore < 85  → price × 1%
在庫ペナルティ  = 「残りわずか」  → price × 1%（bulkモードは5%）
               = 「在庫なし」    → price（購入不可扱い）

最終スコア（低いほど優秀）= (price - ポイント実質価値) + 安全性ペナルティ + 在庫ペナルティ
```

#### 4つの最適化モード

| モード | 説明 |
|--------|------|
| `standard` | 安全性・価格・ポイントをバランスよく評価 |
| `safety_first` | 信頼スコア優先（安全性ペナルティを2倍に） |
| `bulk` | 在庫安定性を最重視（在庫ペナルティを3倍に） |
| `max_points` | ポイント実質価値を1.5倍評価 |

### 2-7. プラットフォーム別 ポイント利用率（`platformProfiles`）

ポイントの「実質価値係数」（usabilityRate）を利用頻度で重み付けする。

|----------------|--------------|------|
| Amazon | 1.0 | highly_used |

| Yahoo!ショッピング | 0.7 | moderate |

| ビックカメラ | 0.2 | rarely_used |

> ヨドバシなど利用頻度の低い店では「10%ポイント還元」でも実質 2.5% 相当として計算するため、表示価格の安さに惑わされない。

### 2-8. キャンペーン管理と上限自動除外

- キャンペーンには `pointCap`（ポイント上限）と `pointsEarned`（獲得済み）を管理
- `isCapped: true` のキャンペーンは最適化計算から自動除外
- 90%以上消化したキャンペーンは「まもなく上限」として警告表示

### 2-9. 出品者信頼スコア（`sellerProfiles`）

プラットフォームの信頼性とは別に、**個別出品者**の信頼スコアも管理：

- `sellerTrustScore`: 0〜100（99=公式メーカー、54以下=危険）
- リスク判定項目: 配送遅延率、返品率、不着率、アカウント年齢、サクラレビューリスク
- 最終スコア = `min(プラットフォーム信頼スコア, 出品者信頼スコア)`

## 8. 既知の問題・注意点

- 楽天 API は `Referer` ヘッダーが「許可されたWebサイト」と完全一致しないと `403 Forbidden` が返る
- Yahoo v3 の `point.amount`（ポイント数）と `point.multiplier`（倍率）は単位が異なり、楽天の `point_rate`（%）とは計算方法が異なる点に注意
- モックデータモード（デフォルト）では `productSearchResults()` が常に固定の2商品を返すため、キーワードは機能しない
- `calcOptimizedScore` と `enrichItem/rankItems` は設計が一部重複している（前者はモック用スコアリング、後者は API 結果の実質価格計算）
